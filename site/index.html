Open coordination protocol

Your agents can think.
They cannot work together.

Nexus is the open protocol that lets AI agents discover each other, talk with end-to-end encryption, and hand off work — across languages, frameworks and organisations. No vendor owns it.

The problem

  
Every multi-agent system reinvents the same broken plumbing.

  

    Frameworks made single agents easy. The moment a second agent appears,
    everyone rebuilds discovery, retries, identity and audit from scratch —
    badly, and incompatibly with everyone else's version.
  


  

    
01

      
Agents can't find each other

      
Addresses get hardcoded. Move an agent and every caller breaks.
         There is no way to ask "who here can translate?"

    
02

      
Work vanishes on restart

      
State lives in memory. A deploy, a crash, an OOM kill — and every
         in-flight task is gone, with nothing recording that it existed.

    
03

      
Nobody can prove what happened

      
When an agent moves money or deletes data, the trail is a log file
         anyone with disk access can rewrite.

    
04

      
The broker reads everything

      
Route through a message bus and it sees every payload in clear.
         Two companies will never agree to that.

    
05

      
Anyone can claim to be anyone

      
Most agent buses take the client's word for its own identity and
         privileges. That is not authentication.

    
06

      
Frameworks don't interoperate

      
A LangChain agent and a CrewAI crew have no common language. Every
         pairing is a bespoke integration.

  






  
How it works

  
One protocol, sitting under whatever you already use.

  

    Nexus is not another agent framework. It is the layer beneath them —
    the part they all assume exists and none of them provides.
  


  
   Python agent            Node.js agent           LangChain / CrewAI
   (native SDK)            (native SDK)            (wrapped, unchanged)
        │                       │                          │
        └──── E2E encrypted ────┴──── RSA-2048 + AES-256-GCM ───┘
                                │
   ═════════════════════════════╪═════════════════════════════
                     N E X U S   H U B
     discovery · identity · JWT auth · RBAC · task lifecycle
             Merkle audit log · rate limiting
   ═════════════════════════════╪═════════════════════════════
                                │
                   hub-to-hub federation
                                │
                     Partner organisation
     Payloads stay encrypted end to end. The hub routes ciphertext
     it cannot read — including across the federation boundary.






  
What you get

  
The parts you would otherwise build yourself.


  

    
🔍
Discovery

      
Find agents by capability, role, metadata or name. Stop hardcoding addresses.

      
discover(capabilities=["translate"])

    
🔐
End-to-end encryption

      
RSA-2048-OAEP wraps a per-message AES-256-GCM key. The hub routes ciphertext it cannot read.

      
on by default

    
🆔
Verifiable identity

      
SHA-256 fingerprints over roles, capabilities and permissions. Tampering is rejected at registration.

      
fingerprint + JWT

    
📋
Tasks that survive

      
Persisted lifecycle. An interrupted task is reassigned when its executor reconnects.

      
pending → running → completed

    
⛓️
Tamper-evident audit

      
Merkle-chained events. Edit one entry on disk and the chain breaks loudly at startup.

      
verify_integrity()

    
🌐
Federation

      
Hubs peer across organisations. Your agents delegate to a partner's without sharing infrastructure.

      
--peer partner=wss://…

    
🔌
Framework adapters

      
Wrap a LangChain chain, CrewAI crew, AutoGen agent or LlamaIndex engine. No rewrite, no new dependency.

      
adapt(my_agent, name="analyst")

    
🖥️
Mission Control

      
Live console for agents, tasks, audit and service accounts. Zero external dependencies.

      
runs on a closed network

What is not done yet

    
    
      
  • No TLS by default — put the hub behind wss:// in production. E2E protects payloads, not metadata.
    • 
      
  • One hub per state database. Multi-hub shared state needs PostgreSQL.
    • 
      
  • Key rotation ejects the fleet; there is no overlap window yet.
    • 
      
  • Executors must be idempotent — a resumed task can run twice.
    • 
      
  • The adapters have not been tested against the real frameworks yet, only against doubles reproducing their calling conventions.
